# 백엔드 개발자 이직 준비 6개월 커리큘럼

> **대상**: 3~4년차 Java/Spring Boot 백엔드 개발자
> **목표**: 6개월 후 중견/유니콘 스타트업 지원 (초기 스타트업 병행)
> **작성일**: 2026-07-21

## 0. 현재 상태 진단

### 보유 자산 (면접에서 팔 수 있는 것)
- **운영 중인 실서비스 경험**: BOMS — 설계/개발/배포/운영 전 사이클
- **장애 대응 실전 경험**: HikariCP/MySQL 커넥션 고갈 인시던트 진단 → 원인 분석 → 재발 방지 체계 구축 (leak-detection, wait_timeout 정합, 헬스체크)
- **인프라/DevOps**: Docker 멀티 프로젝트 아키텍처(proxy-net), Nginx 리버스 프록시, GitHub Actions CI/CD + self-hosted runner
- **AI 엔지니어링**: cric-cs-automation 파이프라인 (Gmail → AI 코드 변경 → SVN → 배포) — 스타트업에서 차별화 포인트
- **테스트 문화**: TDD 워크플로우, @SpringBootTest, MockK

### 갭 (채용공고 표준 세트 대비)
| 영역 | 현재 | 목표 수준 | 우선순위 |
|---|---|---|---|
| 코딩테스트 | 거의 안 해봄 | 백준 실버 안정 + 골드5~4 일부 | ★★★ (매일) |
| CS 기초 (네트워크/OS/DB) | 네트워크 커리큘럼 진행 중 | 경험과 연결해 설명 가능 | ★★★ |
| REST API 설계 | 실무 사용, 원칙 정리 안 됨 | 설계 원칙 근거로 설명 + 리뷰 가능 | ★★★ (조기) |
| Redis | 미경험 | BOMS 실적용 + 캐싱 전략 설명 | ★★☆ |
| 대용량 트래픽 | 미경험 | 부하테스트 실험 + 개선 스토리 | ★★☆ |
| MSA | 이해 부족 | 트레이드오프 중심 설계 토론 가능 | ★★☆ |
| Kafka | 미경험 | 개념 + 사용 시나리오 설명 가능 | ★☆☆ |
| AWS | 미경험 (홈서버 운영) | 프리티어 배포 1회 + 핵심 서비스 개념 | ★☆☆ |

### 핵심 전략 3가지
1. **경력직 면접은 경험 80% + CS 20%** — CS를 교과서로 파지 말고, BOMS 경험에 연결해서 설명하는 연습이 곧 면접 준비다.
2. **BOMS를 실험장으로 쓴다** — Redis 적용, 부하테스트, API 리팩토링을 BOMS에 하면 학습이 곧 이력서 한 줄이 된다.
3. **이력서 초안을 1주차에 쓴다** — 완성용이 아니라 갭 진단용. "쓸 게 없는 칸"이 곧 6개월간 채울 목표다.

## 0-1. 학습 원칙 & 리뷰 운영

### 학습 루프
1. **예측** — 실험/작성 전에 결과를 먼저 적는다
2. **검증** — 실제로 돌려보거나 써본다
3. **불일치 기록** — 예측과 실제가 다른 지점이 **최고 가치의 학습 신호**다. 맞은 것보다 틀린 것을 길게 쓴다
4. **승격** — 관찰을 한 단계 위 원칙(기술) 또는 판단 언어(커리어)로 올린다

### 파일 구조
```
docs/jobprep/
├── README.md          ← 이 파일 (목표·갭·로드맵·원칙)
├── HOLD.md            ← 리뷰 스킬이 자동 생성/관리
└── weekN/
    ├── README.md      ← 주간 목표·완료 기준·재도전 목록
    └── dayNN.md       ← 일자별 기록
```

### 리뷰 스킬 라우팅
각 day 파일 상단의 `리뷰 스킬` 표기를 따른다.

| 대상 | 스킬 | 판정 축 |
|---|---|---|
| 기술 개념·실험·측정 기록 | `study-review` | 기술 정확성 |
| 이력서·경력 재료·협업 스토리·회고 | `career-review` | 검증가능성 (면접 방어) |

- 혼합 파일은 섹션별로 해당 스킬이 자기 영역만 판정한다.
- 두 스킬 모두 PASS 시 자동 커밋·푸시하며, `HOLD.md` 를 공유한다.
- **이력서 파일에 개인정보(연락처·고객사명·회사 내부 정보)를 쓰지 않는다.** 커밋되는 repo 다.

### 완료 기준 공통
- 빈칸 없음 (자리표시자 수준의 서술도 빈칸으로 간주)
- "잘 됐다", "개선했다" 같은 무근거 서술 금지 — 수치나 근거를 함께 적는다

## 2. 월별 상세

### 1개월차 — 기반 다지기: 코테 습관 + 이력서 초안 + REST API

**목표**: 코테를 일상으로 만들고, 이력서 초안으로 갭을 눈으로 확인하고, REST API 설계를 "설명 가능한 지식"으로 전환.

#### Week 1
- [ ] **이력서 초안 작성 (주말 3h)** — 원티드 양식 기준. 잘 쓰려 하지 말고 일단 채운다. 프로젝트별로 "문제 → 해결 → 성과(수치)" 구조로. 빈 칸/약한 칸을 목록화 → 이 문서의 갭 테이블과 대조.
- [ ] 코테 시작: 백준 브론즈~실버5, 매일 1문제. 언어는 Java 유지 (면접 코드리뷰 대비).
- [ ] **입출력 템플릿 확보**: `BufferedReader` + `StringBuilder` + `StringTokenizer`. 백준은 Scanner 로 시간초과가 나는 문제가 흔하다 — 첫날 템플릿을 만들어두고 계속 재사용한다.
- [ ] 시간복잡도/공간복잡도 개념 정리 (코테 리뷰 면접 단골)

#### Week 2~3: REST API 설계 집중
- [ ] 리소스 모델링, HTTP 메서드 의미론, 상태코드 선택 기준, 멱등성
- [ ] URI 설계 원칙 (명사/계층/쿼리 파라미터), 버저닝 전략 비교 (URI vs 헤더)
- [ ] 에러 응답 설계 (RFC 7807 Problem Details), 페이지네이션 3방식 비교 (offset / cursor / keyset)
- [ ] **실습**: BOMS API 전체를 표로 뽑아 셀프 리뷰 — 원칙 위반 사례 찾기 → 개선안 작성 (실제 수정은 선택). 이 리뷰 문서 자체가 면접 소재가 된다.
- 추천 자료: 그랄 웹 API 디자인 서적 1권 or MS/Google API Design Guide 정독

#### Week 4
- [ ] 코테: 스택/큐, 해시 유형 (solved.ac 클래스 2~3 + 알고리즘 분류 태그 활용)
- [ ] REST 학습 정리: "왜 PUT이 아니라 PATCH인가", "왜 200이 아니라 204인가"를 BOMS 사례로 답변 스크립트화
- [ ] 월간 회고: 코테 정답률, 이력서 갭 목록 업데이트

---

### 2개월차 — CS 기초 본격화 + Redis 입문

**목표**: 진행 중인 네트워크 커리큘럼을 면접 답변 형태로 수렴시키고, OS 기초 시작. Redis 로컬 실습.

#### Week 5~6: 네트워크 (기존 커리큘럼 연계)
- [ ] TCP 3-way/4-way handshake, TIME_WAIT — **HikariCP 인시던트와 연결해서** 설명 스크립트 작성 ("커넥션 풀이 왜 필요한가"를 TCP 비용으로 설명)
- [ ] HTTP/1.1 vs 2 vs 3, keep-alive, HTTPS/TLS 핸드셰이크
- [ ] 로드밸런싱 L4 vs L7 — Nginx 운영 경험과 연결
- [ ] netshoot으로 실험 1회 이상 (기존 breakage 실험 방식 유지)

#### Week 7~8: OS 기초 + Redis 시작
- [ ] 프로세스 vs 스레드, 컨텍스트 스위칭, 멀티스레딩 동기화 (Java 스레드 모델과 연결)
- [ ] 블로킹/논블로킹, 동기/비동기 — Tomcat 스레드 풀 관점에서
- [ ] **Redis**: 자료구조 5종, TTL, 영속화(RDB/AOF), 로컬 Docker로 실습 (proxy-net 패턴에 컨테이너 추가)
- [ ] 코테: 정렬, 완전탐색 유형. 실버4~3 진입

---

### 3개월차 — DB 심화 + Redis 실적용

**목표**: DB를 면접 최대 무기로 만들기 (인시던트 경험 보유 영역). Redis를 BOMS에 실제 적용해 이력서 한 줄 만들기.

#### Week 9~10: DB 심화
- [ ] 인덱스: B+Tree, 커버링 인덱스, 실행계획(EXPLAIN) — **BOMS 실제 슬로우 쿼리 1개를 잡아 개선** (before/after 수치 기록)
- [ ] 트랜잭션: ACID, 격리수준 4단계와 각 이상현상 — MySQL 로컬에서 직접 재현 실험
- [ ] 락: 공유/배타, 낙관적/비관적, 데드락 — JPA @Version 실습
- [ ] 커넥션 풀 심화: HikariCP 파라미터 전체 리뷰 (이미 경험한 인시던트를 이론으로 완성)

#### Week 11~12: Redis → BOMS 적용
- [ ] 캐싱 전략 (look-aside, write-through 등) + 캐시 무효화 문제
- [ ] **실전**: BOMS에서 조회 빈도 높은 데이터(예: 학회 정보, 등록 현황) 1곳에 Spring Cache + Redis 적용 → 응답시간 before/after 측정
- [ ] 세션 스토어 / 분산 락으로서의 Redis 개념 정리
- [ ] 코테: DFS/BFS 시작 (최대 고비 구간 — 이 유형만큼은 대표 문제 암기 수준으로 반복)

### 4개월차 — 대용량 트래픽 실험 + MSA 이론

**목표**: "대규모 경험 없음"을 "한계를 측정하고 개선해 본 경험 있음"으로 바꾸기. MSA를 트레이드오프 언어로 이해.

#### Week 13~14: 부하테스트 실험
- [ ] k6 (또는 nGrinder) 학습 → **BOMS 등록 API에 부하테스트**: 어디서 먼저 터지는가? (Tomcat 스레드? HikariCP? MySQL? Nginx?)
- [ ] 병목 지점별 튜닝 실험: 스레드 풀 / 커넥션 풀 / Nginx worker — 각 파라미터 변경의 예측 → 측정 → 불일치 기록
- [ ] 결과를 기술 블로그 or 정리 문서로: "동시 등록 N명까지 버티는 시스템 만들기" — 이력서 + 면접 핵심 스토리
- ※ 실서비스 트래픽이 없어도, **한계를 직접 측정하고 병목을 규명한 경험** 자체가 채용공고의 "트래픽을 버티는 구조 이해"에 대응한다.

#### Week 15~16: MSA 이론
- [ ] 모놀리스 vs MSA: 장단점을 "언제 쪼개면 안 되는가" 관점까지 (면접에서 무조건 MSA 찬양은 감점)
- [ ] 핵심 패턴: API Gateway, Service Discovery, 서킷 브레이커, Saga/이벤트 기반 정합성, 분산 트랜잭션이 어려운 이유
- [ ] 조직 관점: 콘웨이 법칙, MSA 전환 비용
- [ ] **연습**: "BOMS를 MSA로 쪼갠다면?" 설계 문서 1장 작성 — 경계 나누기(등록/결제/알림), 서비스 간 통신, 데이터 분리 문제. 결론이 "지금 규모에선 모놀리스가 맞다"여도 좋음 — 그 근거가 곧 이해도.
- 추천 자료: 마이크로서비스 패턴(크리스 리처드슨) 핵심 장 / 관련 컨퍼런스 발표(if kakao, DEVIEW, 우아콘) 3편

### 5개월차 — 기술면접 집중 + AWS + 이력서 완성

**목표**: 답변을 입으로 만드는 달. 서류 제출 준비 완료.

#### Week 17~18: Spring/JPA 심화 (기술면접 1순위 영역)
- [ ] Spring: IoC/DI, Bean 스코프/라이프사이클, AOP와 @Transactional 동작 원리(프록시), 트랜잭션 전파
- [ ] JPA: 영속성 컨텍스트, 1차 캐시/더티체킹, N+1 문제와 해결 3가지, OSIV, fetch 전략
- [ ] 각 주제를 **BOMS 코드에서 실제 사례 찾아** 답변 스크립트화 (예: "N+1을 실제로 겪고 fetch join으로 해결한 곳")
- [ ] 예상 질문 100선 목록 만들고 音성으로 답변 녹음 → 다시 듣기 (쓰는 것과 말하는 것은 다르다)

#### Week 19~20: AWS 기초 + 이력서/포트폴리오 완성
- [ ] AWS 프리티어: EC2 + RDS + S3로 토이 배포 1회 (홈서버 경험을 클라우드 언어로 번역: "launchd → systemd/user-data", "포트포워딩 → 보안그룹")
- [ ] VPC/서브넷/보안그룹, IAM, ALB 개념 — 네트워크 커리큘럼 지식 재활용
- [ ] **이력서 완성**: 1주차 초안 대비 채워진 갭 확인. 모든 항목을 "문제 → 행동 → 수치 성과"로. 부하테스트/Redis/인시던트 스토리 배치.
- [ ] 포트폴리오: GitHub README 정비 + 정리 문서(블로그/노션) 링크. 별도 화려한 포트폴리오보다 **깊이 있는 기술 정리 글 3~4편**이 낫다.
- [ ] 지인/커뮤니티에 이력서 리뷰 요청 1회 이상

### 6개월차 — 실전 지원 + 회고 루프

**목표**: 지원-피드백 루프 돌리기. 탈락도 데이터다.

#### Week 21~22

## 3. 유형별 코딩테스트 로드맵 (병행 트랙)

| 기간 | 유형 | 목표 |
|---|---|---|
| 1개월차 | 브론즈~실버5, 구현/문자열/배열 | 매일 습관화, 입출력 템플릿 체화 |
| 2개월차 | 스택/큐, 해시, 정렬, 완전탐색 | 실버4~3 진입 |
| 3개월차 | DFS/BFS (최중요), 그리디 | 대표문제 반복 암기 |
| 4개월차 | 이분탐색, 투포인터, DP 기초 | 실버 안정, 골드5 진입 |
| 5개월차 | 실전 세트 + **프로그래머스 환경 적응** (기출 1~2세트) | 골드5~4 일부 |
| 6개월차 | 실전 유지 + 풀이 설명 연습 | 코드리뷰 면접 대응 |

**원칙**
- 30분 룰: 30분 못 풀면 풀이 보기 → 안 보고 재구현 → 3일 후 재도전
- 경력직 목표는 골드 상위권이 아니라 **실버 안정 + 골드5~4 일부**. 그 이상 투자하면 다른 영역 손해.
- 학습은 백준으로 하되, **국내 기업 코테는 프로그래머스 플랫폼에서 치르는 경우가 많다.** 백준은 표준입출력을 직접 다루고 프로그래머스는 함수 시그니처가 주어지므로, 5개월차에 프로그래머스 환경을 1~2세트로 익혀둘 것.
- 진척도는 solved.ac 티어/클래스로 추적한다 (정답 수보다 티어 분포가 실력을 잘 보여준다).
- 풀이를 말로 설명하는 연습 병행 (코테 후 리뷰 면접 대비)

## 4. 면접 스토리 뱅크 (지금부터 축적)

경력직 면접의 80%는 경험 질문. 아래 스토리를 "상황 → 문제 → 행동 → 결과 → 배운 것" 구조로 미리 문서화:

1. **HikariCP/MySQL 커넥션 고갈 인시던트** — 장애 대응의 정석 스토리 (진단 → 임시조치 → 근본원인 → 재발방지 체계)
2. **부하테스트로 시스템 한계 규명** (4개월차에 생성) — 트래픽/성능 역량 증명
3. **Redis 캐싱 도입** (3개월차에 생성) — 기술 도입 의사결정 과정
4. **멀티 프로젝트 Docker 아키텍처 설계** — proxy-net 패턴, 왜 이렇게 설계했나
5. **CI/CD 구축 + stale-code 배포 이슈 해결** — 자동화 + 트러블슈팅
6. **AI 파이프라인(cric-cs-automation) 구축** — 문제 정의부터 자동화까지, 차별화 카드
7. **컨텍스트 초과 문제를 5-skill 파이프라인으로 해결** — 시스템적 사고 증명
8. (약점 질문 대비) SVN 환경, 소규모 팀 — "제약 속에서 어떻게 좋은 practice를 만들었나"로 반전
